# 游戏代码审核

以资深游戏开发者身份，对代码实现进行全面审核。

## 审核流程

### 1. 架构审核

首先检查 **ECS 模式合规性**，使用配套脚本验证：

```bash
python scripts/check_ecs_compliance.py <src-path>
```

检查要点：
- **Components**：仅包含数据结构（Interface/Type），**禁止包含逻辑**
- **Systems**：必须是**纯函数**，接收 World 和 deltaTimeMs 参数
- **Blueprints**：定义实体初始配置，不包含运行时逻辑
- **事件系统**：所有事件必须**本帧生成和消费**，禁止跨帧传递
- **目录隔离**：代码位于 `src/engine/`，禁止在 `game/` 废弃区修改

### 2. 代码质量审核

参考 [审核检查清单](references/checklist.md)，逐项验证：

- **类型安全**：禁止使用 `any`，优先使用可组合 Interface
- **时间单位**：所有时间相关变量统一使用**毫秒 (ms)**，变量名以 `ms` 结尾
- **JSDoc 注释**：Systems 必须说明处理组件、逻辑目的、副作用
- **职责分离**：单一职责原则，避免过度耦合

### 3. 性能审核

参考 [性能审核指南](references/performance-guidelines.md)，检查：

- **循环效率**：避免 O(n²) 及以上复杂度
- **内存分配**：避免在热路径中频繁创建对象
- **事件处理**：事件队列本帧清空，无累积
- **渲染优化**：批量处理、脏标记、空间分区

### 4. 测试覆盖审核

运行测试覆盖率分析：

```bash
python scripts/analyze_test_coverage.py <test-path>
```

检查要求：
- **单元测试**：位于 `./tests` 目录
- **核心流程覆盖**：主要逻辑路径必须有测试
- **边界条件**：Edge Cases 有对应测试
- **所有命令通过**：`pnpm lint`、`pnpm test`、`pnpm build`

### 5. Bug 检测

使用系统性方法检测潜在 Bug：

- **空值处理**：可选链正确使用
- **边界检查**：数组越界、数值范围
- **状态一致性**：组件状态与实际状态同步
- **竞态条件**：事件处理顺序正确性
- **资源泄漏**：监听器、定时器正确清理

## 审核输出格式

审核完成后，输出结构化报告：

```markdown
# 代码审核报告

## 架构合规性
- ECS 模式: ✅ / ❌
- 职责分离: ✅ / ❌

## 代码质量
- 类型安全: ✅ / ❌
- JSDoc 注释: ✅ / ❌
- 命名规范: ✅ / ❌

## 性能评估
- 算法复杂度: ✅ / ❌
- 内存使用: ✅ / ❌

## 测试覆盖
- 单元测试: ✅ / ❌
- 核心流程覆盖: ✅ / ❌

## 发现的问题
1. [严重/中等/轻微] 问题描述
   - 位置: file.ts:line
   - 建议: 修复方案

## 改进建议
- 建议 1
- 建议 2
```

## 审核原则

1. **严格但建设性**：指出问题同时提供解决方案
2. **项目规范优先**：严格遵循 CLAUDE.md 中的规范
3. **实用主义**：在理论完美和实际可维护性间平衡
4. **可操作性**：每个问题都有明确的修复路径
